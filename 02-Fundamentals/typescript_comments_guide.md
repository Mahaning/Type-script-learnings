# 💬 The Complete Guide to Comments in TypeScript

Comments in TypeScript serve two major purposes: **human readability** (documentation, context, and developer experience) and **compiler instruction** (type checking rules, suppressions, and JSDoc/TSDoc metadata).

---

## 📌 1. Basic Comment Types

TypeScript inherits JavaScript's basic comment syntax.

### A. Single-Line Comments (`//`)
Best for short inline explanations or quick toggles.

```typescript
// Define user status flag
const isActive: boolean = true;
```

### B. Multi-Line Comments (`/* ... */`)
Best for block-level descriptions or temporarily disabling blocks of code.

```typescript
/* 
  The following logic calculates tax estimates
  based on federal and regional rates.
*/
function calculateTax(amount: number): number {
  return amount * 0.15;
}
```

## 📚 2. Modern Documentation Comments (JSDoc / TSDoc)

Documentation comments (`/** ... */`) are parsed by code editors (like VS Code) to display rich, styled hover cards and autocompletion hints.

```
       Write JSDoc / TSDoc                    VS Code Hover Preview
┌─────────────────────────────┐         ┌───────────────────────────────┐
│ /**                         │         │ calculateDiscount(price, rate)│
│  * Applies a promo code     │ ──────► │ Applies a promo code          │
│  * @param price Item price │         │ @param price Item price       │
│  */                         │         └───────────────────────────────┘
└─────────────────────────────┘
```

### A. Annotating Functions

```typescript
/**
 * Calculates the discounted price for a given item.
 * 
 * @param price - The initial price of the item (must be positive).
 * @param discountRate - Discount percentage between 0 and 1 (e.g., 0.2 for 20%).
 * @returns The final price after discount.
 * 
 * @throws {Error} If price or discountRate are negative.
 * 
 * @example
 * ```typescript
 * const finalPrice = applyDiscount(100, 0.2); // Returns 80
 * ```
 */
function applyDiscount(price: number, discountRate: number): number {
  if (price < 0 || discountRate < 0) {
    throw new Error("Invalid pricing values");
  }
  return price * (1 - discountRate);
}
```

### B. Annotating Interfaces and Object Properties

```typescript
/** Represents an active system user */
interface UserAccount {
  /** Unique ID generated by the database */
  readonly id: string;
  
  /** Display name shown in user profile */
  name: string;

  /** 
   * User role permissions level.
   * @deprecated Use `permissions` array instead.
   */
  role: string;
}
```

## 🛑 3. TypeScript Compiler Directives

TypeScript provides special single-line directives starting with `@ts-` that instruct the compiler to alter how it checks specific lines.

### A. `@ts-expect-error` *(Recommended)*
Suppresses the error on the **very next line**, but **fails compilation if no error is actually present**. Ideal for testing error states.

```typescript
// @ts-expect-error - Passing a string to a function expecting a number for testing
calculateTax("invalid_number");
```

### B. `@ts-ignore` *(Use sparingly)*
Silences any TypeScript compiler error on the next line unconditionally.

```typescript
// @ts-ignore - Ignore legacy JS library missing types
window.legacyPlugin.init();
```

> 💡 **Best Practice:** Prefer `@ts-expect-error` over `@ts-ignore`. `@ts-ignore` leaves silent debt when code updates fix the underlying type issue.

### C. `@ts-nocheck`
Disables type checking for an **entire file**. Place it at the top of the file.

```typescript
// @ts-nocheck
// This entire file will skip TypeScript validation
let price: number = "hello"; // No error reported
```

### D. `@ts-check`
Enables TypeScript type checking inside regular `.js` or `.jsx` files.

```javascript
// @ts-check

/** @type {number} */
let age = 25;

// TS Error reported in plain JS!
age = "twenty five";
```

## ⚡ 4. Common JSDoc & TSDoc Tags Matrix

| Tag | Target | Description |
| :--- | :--- | :--- |
| `@param` | Function Parameters | Explains variable expectations & units |
| `@returns` / `@return` | Function Output | Explains return value |
| `@throws` | Exceptions | Documents runtime errors thrown |
| `@deprecated` | Any declaration | Marks features as obsolete (renders strike-through in editor) |
| `@see` | Any declaration | Links to external URLs or related methods |
| `@example` | Any declaration | Provides executable code snippets |
| `@readonly` | JS Properties | Hints that a property should not be mutated |

## 🛠️ 5. Automated Documentation Tools

You can convert your JSDoc and TSDoc comments into HTML documentation sites using automated CLI generators:

1. **[TypeDoc](https://typedoc.org/):** Reads your TypeScript codebase and JSDoc comments to generate full HTML documentation pages.
   ```bash
   npx typedoc --out docs src/index.ts
   ```
2. **VS Code Built-in Support:** Automatically previews all JSDoc formatting in hover tooltips without requiring third-party tools.
